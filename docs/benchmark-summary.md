# Benchmarks

The models, their settings and the thresholds of the service were chosen by measurement; the OCR engine, the vector store and the concurrency model were judgement calls ([Design](../DESIGN.md) section 2). This page is the summary: the terms used, how the measurements were made, and the headline result of each study. The full record, with every table, interval and source file, is the [benchmark record](BENCHMARKS.md); section numbers below refer to it.

## Glossary

| Term | Meaning |
|---|---|
| OCR | Optical character recognition: reading the text of a scanned page, word by word, with each word's box. |
| NER | Named-entity recognition: a model that marks which words are a person's name. |
| RAG | Retrieval-augmented generation: find the relevant passages, then let a language model (LLM) answer from them alone. |
| KYC | Know-your-customer forms: identity documents a compliance team collects. |
| `psm 3` | Tesseract's fully automatic page segmentation mode. |
| OpenMP | The threading library Tesseract uses inside one process; `OMP_THREAD_LIMIT=1` keeps each process on one thread. |
| mBERT | Multilingual BERT, an older multilingual model used as a NER baseline. |
| PDFium, Tesseract | PDFium (Google's PDF engine, used through `pypdfium2`) draws each page as an image; Tesseract is the open-source OCR engine that reads it. |
| XLM-R, e5 | `xlm-roberta-base-ner-hrl` is the multilingual NER model; `multilingual-e5-base` is the multilingual embedding model. |
| Qdrant | The vector database that stores the chunks and their embeddings and finds the most similar ones. |
| Ollama, Gemma 4 e4b | Ollama serves language models locally on the GPU; Gemma 4 e4b is Google's small Gemma 4 model it serves. "Thinking off" asks it to answer without a reasoning phase. |
| Prompt Guard 2 | Meta's small classifier that scores a text for instructions aimed at a language model (prompt injection). |
| CER | Character error rate of the OCR: share of characters read wrong. Lower is better (5.4 % with the chosen settings, 16.0 % without flattening). |
| Fuzzy name recall (OCR) | Share of the printed names that can still be found in the OCR text despite small reading errors. It measures OCR only, not the whole extraction. |
| Precision, recall, F1 | Precision: share of the reported names that are real names. Recall: share of the real names that are reported. F1: their harmonic mean. A name counts only if its box overlaps the true box by at least half (IoU >= 0.5). |
| IoU | Intersection over union of two boxes: 1 is the same box, 0.5 means they share half of their combined area. |
| Decoy | A generated name of a different person, close in spelling to a requested one, used to count false matches. |
| Embedding, cosine | An embedding turns a text into a vector; texts with similar meaning get vectors with a high cosine similarity (at most 1). |
| Recall@5 | Share of questions whose answer is in one of the 5 retrieved chunks. Higher is better. |
| Answer in context | Share of questions whose answer is in the passages sent to the LLM. |
| Relevance threshold (0.808) | If no retrieved chunk scores at least this cosine, the service refuses without calling the LLM. |
| Support share | Share of the answer's content words that appear in the passages the LLM saw; below 0.6 the answer is replaced by the refusal. |
| Accuracy (LLM) | Share of answerable questions whose answer contains the expected answer; a refusal counts as wrong. |
| p95 | 95 % of requests are faster than this. |
| docs/min | Throughput: documents processed per minute. |
| fp16, fp32 | Half and full floating-point precision of a model on the GPU; half uses half the memory. |
| Bootstrap interval | The range a score would move in if the documents or questions had been drawn again: about a thousand resamples, and the middle 95 % is reported. |
| Paired comparison | Two configurations scored on the same items; the difference per item removes how hard each item is, so small real differences become visible. |

## Method

- **A synthetic corpus, because real labelled scans were not available.** 600 image-only business PDFs (memos, minutes, contracts, KYC forms, reports, invoices, letters), 120 per language (en, es, pt, fr, de), 1,045 pages, three noise levels (40 % clean, 40 % medium, 20 % hard). Ground truth: 7,489 person mentions with their boxes, 2,425 trap spans (organisations, streets, products), 2,871 answerable and 300 unanswerable questions, 200 name lists with decoys. It is generated by a seeded generator, so it is reproducible (section 1).
- **Intervals and paired comparisons.** Quality figures carry a 95 % bootstrap interval, and two configurations are compared on the same items; a difference whose interval crosses zero is treated as no difference. Throughput and latency figures are repeated passes, reported as their range.
- **Candidates.** The suggested stack of the assignment, plus the alternatives a public benchmark ranked high for each task (13 NER models, 9 multilingual embedders, 3 local language models that fit a 12 GB GPU, one hosted reference).
- **Measured where it runs.** OCR and the service measurements ran in the Linux images of this repository; throughput was measured on the deployed compose stack with CPU quotas of 16, 8 and 4 CPUs (one host: Ryzen 7 7700X, 32 GB, RTX 4070 Ti).
- **The measurement scripts are not part of this repository.** Each result table names the result file it was copied from and the method, so a study can be repeated.

## Caveats that apply to every number

- **The corpus is synthetic.** Template text, fixed name pools and fact-lookup questions make retrieval and matching easier than on real documents. Paired comparisons between configurations are the reliable signal; absolute scores are optimistic (section 1, section 10). That is also why keyword search (BM25), which won the retrieval diagnostic here because the generated questions quote exact names, was not adopted (section 12).
- **Tuned on the reporting data.** The rules and thresholds were chosen on the same corpus they are reported on; there is no held-out split (section 10). The procedure below recalibrates them on real documents.
- **One host.** Timings come from one machine, its smaller sizes as CPU quotas. Re-measure on the target hardware before sizing a deployment.

## Recalibration procedure

The relevance (0.808), match (0.90) and injection (0.5) thresholds are environment settings. Before a real deployment:

1. Collect a few hundred labelled questions on documents of the target domain, answerable and unanswerable, in the expected languages, and name lists with real near-miss names.
2. Ingest the documents and run retrieval only (no LLM), recording the best score of every question.
3. Take the highest relevance threshold that still keeps 95 % of the answerable questions, and report its refusal rate on the unanswerable ones with a bootstrap interval. Set the match threshold just above the highest score of a near-miss name of another person.
4. Score the domain's own pages with the detector and read the flagged ones before trusting `INJECTION_THRESHOLD`.
5. Set the values in the environment; no code change is needed.
